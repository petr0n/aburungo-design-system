Foundations

The eight decisions everything else is built out of, rendered live from src/tokens.css and src/brand.css — not a copy, so none of it can drift from what ships. Each group states the rule that governs it, quoted from DESIGN.md. Dashed Akane is what does not exist yet: the gap is drawn rather than described.

The verdict glyphs sit at the 800 step, not 500. At 500 they were the literal brand values a book's chrome wears, so a ○ could land in exactly its own header band's colour — and 500-on-tint measured 3.98:1. Both fixed 2026-08-21.

The No Raw Value Rule. Components reference role tokens, never hexes. Enforced by scripts/check-adherence.mjs, which fails the build.

The Accent Is An Input Rule. A card's accent is a prop, not a constant. Colour carries meaning — which scenario, which state. Pick from the set; never invent a hex.

The One Dark Slab Rule. The header band is Sumi-iro. Nothing else on the same screen is near-black — the kana keyboard is Rokushō for exactly this reason.

The Japanese Gets More Air Rule. JP line-heights run substantially looser than their Latin equivalents at the same size — 28px on 18px, 48px on 32px. Kanji density and furigana both need the room. Never apply a Latin line-height to Japanese text.

The Prompt Is The Product Rule. On any study surface the Japanese phrase is the largest element on screen. If a button is competing with the phrase, the button is wrong.

03 · Shape degenerate by design

Six radius names. Five of them resolve to the same 4px and are rendered side by side so the degeneracy is visible rather than asserted — sm, md, lg, xl and 2xl are indistinguishable below, and that is correct.

--radius-sm
--radius-md
--radius-lg
--radius-xl
--radius-2xl
--radius-full

Flattened 2026-08-16. The scale used to run 6px for small chrome up to 20px for the review card — sound reasoning, and it made the UI look like a friendly consumer app. One tight radius reads as a lacquered panel, which is the Zuihōden reference. The names are kept and all point at one value on purpose: components go on asking for a radius by role, so restoring a scale is a six-line edit in src/tokens.css rather than a repo-wide sweep. Do not collapse the call sites down to one token.

--radius-full is the exception and is not 4px: it is the hanko and the maru, which are circles by cultural logic rather than styling. A hanko is round because seals are round; ○ means correct in Japanese schooling whatever this product decides. Nothing else in the system is a pill.

04 · Elevation solid

Four shadow tokens, each on the surface it was tuned for — a shadow on the wrong ground tells you nothing. Depth in this system is carried by tone: paper on warm paper on mist. Three of the four are hairlines; only --shadow-glass has any depth, and it earns it by lifting a panel off a textured ground where a hairline registers as nothing.

The Two Shadows Rule. If a new component wants a third shadow, it wants tonal separation instead. Reach for a surface token before a shadow.

Stated as two, shipping as four. --shadow-glass arrived 2026-08-13 as the sanctioned exception (the blur does legibility work, not decoration) and --shadow-key-on-inverse is the key hairline restated for the dark keyboard — the same shadow, not a new tier. The rule's intent holds; its arithmetic in DESIGN.md does not, and the values quoted there are still v2's plum tint.

05 · Motion thin

Two animations for the whole system, both owned by FlipCard, both looping below so they can actually be seen. There is no vocabulary for transitions, state changes, reveals, page entry, or the loading spinner — those are written ad hoc where they are needed. DESIGN.md caps MOTION_INTENSITY at 3 on every surface, so the gap is a small one to close deliberately, not a licence to add flourish.

absent

Reduced motion is honoured in the tokens, not at the call site. src/tokens.css neutralises both animations to none under prefers-reduced-motion: reduce — scoped to these two rather than a blanket * { animation: none }, so motion that carries meaning survives. It lives in tokens.css because the consuming app imports that file and never touches src/index.css.

Found while building this page, and fixed: the guard and the @keyframes reached the four harness HTML files but not dist/tokens.plain.css, which is what all 27 preview pages import — so the animation tokens named keyframes that did not exist, and preview/00-inventory.html was captioning a still frame “card-enter”. build-tokens computed the trailing block after writing the sheet. Measured: 3 matches in the source, 0 in the generated sheet. Now 3. Typecheck, lint and the contrast gate stayed green throughout — none of them can see a missing @keyframes.

The two specimens above deliberately declare no keyframes of their own. They animate only because the generated sheet carries them, which makes this section the thing that catches the regression if it ever comes back. A page-local copy would keep animating and hide it.

Nothing exists. Not a placeholder — a genuinely empty layer, and the largest hole in the system: the product is practical Japanese for real situations and there is not one picture of a situation anywhere in the repo. DESIGN.md's Material section names it as absence #4, the one furthest from being decided.

The direction is set; the assets are not. Japanese woodblock (mokuhanga) in the aizuri-e manner — deep indigo carrying the line work, flat colour with no gradients, carved chatter on the edges, a fraction of a millimetre of registration offset, laid-paper grain. Explicitly not anime. Five self-contained prompts sit in docs/illustration-prompt.md, one per Book One chapter.

Skill output is reference art, never a shipped asset: it lands in preview/_sandbox/, and a drawn asset still comes out of Affinity. No approved image has reached assets/. Until one does, twelve Book One chapters have no art.

The Patterned Ground Rule. A bare .emboss-bg ground carries fg, fg-heading and fg-muted only. fg-subtle and fg-faint are barred at 3.47:1 — unless they sit on .glass, which is what that utility is for. Text is judged against the darkest pixel of the tile, not against the surface token. This is not an opacity problem: carrying fg-subtle needs roughly .16, by which point the pattern is invisible. Do not put glass on a patterned well — 4.47:1, the one measured combination that fails.

The Maru Boundary Rule. A maru marks an answer. It never accumulates. Transient and per-answer is annotation; persistent and per-user is a badge. The moment a maru survives onto a profile screen, it has become gamification. The crest obeys the same boundary from the other side: kamon are circular and ○ is taken, so a patterned ground stays away from any surface where an answer is being judged.
